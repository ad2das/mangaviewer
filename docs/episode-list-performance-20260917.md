# 회차 목록 표시 속도 개선 — 2026-09-17

네 사이트의 회차를 먼저 도착한 페이지부터 표시하고, 완성된 목록은 저장해서 재진입 시 재사용한다. 오래된 목록은 유지하면서 갱신하며, 회차 옆 새로고침 버튼으로 즉시 최신 목록을 요청할 수 있다.

## 실측 결과

Android API 35 에뮬레이터에서 실제 AppGraph·ViewModel·네트워크로 각 사이트의 `화산귀환`을 열었다. 아래 시간은 선택 요청부터 사용할 수 있는 회차 상태를 관측할 때까지이며, 디스플레이의 첫 픽셀이나 앱 시작 시간을 측정한 값은 아니다. 각 조건의 단일 측정으로, 외부 서버·네트워크 캐시·기기 부하에 따라 달라진다.

| 사이트 | 기존 첫 목록 준비 | 개선 후 첫 목록 준비 | 첫 표시 / 최종 회차 수 | 개선 후 전체 수집 완료 | 재진입: 기존 → 개선 |
|---|---:|---:|---:|---:|---:|
| NTK | 545ms | 461ms | 186 / 186 | 461ms | 126ms → 305ms; 추가 측정 21ms |
| WFWF | 1,881ms | 893ms | 100 / 186 | 1,319ms | 948ms → 1ms |
| 뉴엑스툰 | 37,909ms | 2,421ms | 20 / 185 | 30,327ms | 31,215ms → 3ms |
| 굿툰 | 1,183ms | 531ms | 186 / 186 | 870ms | 1,071ms → 14ms |

뉴엑스툰은 10페이지를 모두 기다리던 구조를 바꿨다. 첫 20개부터 사용할 수 있고 나머지는 계속 수집한다. 전체 수집 시간이 2.4초라는 뜻은 아니다. 굿툰은 첫 응답에 186개가 있어도 다음 페이지 확인이 끝날 때까지 수집 중으로 표시한다. NTK는 기존에도 빨랐으며 재진입 수치에 변동이 있어 모든 측정이 개선됐다고 주장하지 않는다.

완료된 회차 ID와 순서를 기존 결과와 대조해 네 사이트 모두 동일함을 확인했다. 중복 ID는 없다. 새 Activity에서 다시 열었을 때는 NTK 57ms, WFWF 34ms, 뉴엑스툰 43ms, 굿툰 32ms였다. 앱 프로세스를 종료한 뒤 뉴엑스툰을 열었을 때도 디스크의 185개가 377ms에 준비됐다. 이 경우 목록이 오래되어 백그라운드 갱신은 28,801ms에 완료됐다.

## 동작과 정확성

- 완료된 목록만 메모리와 디스크에 저장한다. 메모리는 최대 16개 작품·50,000회차, 디스크는 최대 32개 파일·16MB로 제한한다. 파일은 원자적으로 교체하고 손상된 파일은 무시한다.
- 2분 이내 목록은 재사용한다. 이후에는 기존 목록을 보여주면서 갱신한다. 수동 새로고침은 이 시간과 관계없이 요청하며, 선택한 탭과 회차를 유지한다.
- 부분 목록에는 수집 중임을 표시한다. 아직 첫 회차를 확정할 수 없으므로 전체 다운로드와 바로 읽기는 완료 후 활성화한다. 표시된 개별 회차는 즉시 열 수 있다.
- 수집 실패·취소·다른 작품으로 이동했을 때 부분 목록을 완성된 목록으로 저장하지 않는다. 다운로드된 일부 회차로 대체 표시한 경우도 완성 목록으로 저장하지 않는다.
- 상세 화면에서는 검색·부가정보·홈 요청을 잠시 멈추고, 뒤로 돌아가면 검색 커서와 결과를 이어간다. 읽기 사전 준비는 사용할 목록이 생긴 뒤 시작한다.
- 뉴엑스툰의 요청 간격과 서버 제한은 유지한다. 전체 수집에 2분 이상 걸려도 새로운 회차가 도착하면 계속 진행한다. 새 회차가 2분 동안 도착하지 않으면 요청을 취소하고 재시도를 안내한다.

## 검증 및 재현

관련 단위 테스트 775개(app 258, data 143, NTK 187, WFWF 86, 뉴엑스툰 36, 굿툰 65), APK 빌드, lint, 기존 구조 검사(407개 파일)가 통과했다. 페이지 진행, 긴 수집과 정지 구분, 캐시 원자성, 취소 경쟁, 오프라인 분리, 새로고침을 검사했다. 실제 네 사이트 회차 측정, 프로세스 재시작, 검색 UI 3개 검사도 통과했다. 실제 새로고침 버튼을 눌러 185개 목록과 회차 탭이 유지되는 것을 확인했다.

`EpisodeListLatencyDeviceTest`는 외부 사이트를 호출하는 선택 실행 검사다. `episodeAuditLabel`로 증거 디렉터리를 지정하며, `#ntk`, `#wfwf`, `#newxtoon`, `#goodtoon`으로 개별 실행할 수 있다. 이 검증은 사이트별 한 작품의 실측과 별도 회귀 테스트이며 모든 작품·향후 서버 응답을 보장하지 않는다.
